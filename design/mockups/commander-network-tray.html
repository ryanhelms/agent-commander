Commander network: relay servers and the command-center tray

Design proposal, 25 November 2026. Source of truth: design/COMMANDER-NETWORK-SERVERS.md. All names and data below are fictional.

  • You enter the relay servers. Type a host or URL once. Commander saves it. The build-time relay address goes away.
  • Several connections stay live. The device agent holds one connection per enabled server, and friends are grouped by server.
  • Trust is pinned on first use. You confirm the certificate fingerprint when you add a server. A changed certificate blocks that server and asks you.
  • This Mac can host a relay natively. One relay process, bundled PostgreSQL and embedded NATS run under launchd. Friends reach it over Headscale or any network that resolves the host.

c. Command-center home: what each band shows

  • Inc 1Tally row and server list: status per server, favorites first, server colour, last seen when offline.
  • Inc 1Friends grouped by server, friend requests, and the existing Share action.
  • Inc 2My presence set automatically (busy while agents run), linked-contact badges, activity feed with filters.
  • Inc 3Approval prompts and access requests in “Needs you”. Hand-off rows in live remote work.
  • Inc 4Watch rows in live remote work.

The tray grows from 360 pt to 400 pt wide and scrolls past the height of the screen. Every status has a shape and a word as well as a colour. The main cockpit redesign is out of scope here and comes later.

The other tray states

Each state is the same 400 pt menu-bar popover. Switch the tray theme above: every mockup is drawn from the same tokens.

How the pieces connect

Every Mac dials out to each relay on port 443. A relay routes sealed envelopes and cannot read them.

What ships when

From the spec’s delivery order. Each increment ends verified on this Mac and a second Mac over Headscale.

1. Connect (a, b, c, d, e)

  • Add server and the five-step health check

  • Server list: favorites, recents, status per server
  • Friends grouped by server
  • Native host mode with a first admin; Hosting start and stop, bind address, members (assumed)

3. Share and consult (c, f)

  • Approval prompts, Ask each time or Auto within limits

4. Live work (c)

  • Watch rows in live remote work

5. Teams

  • Groups under each server, shared workspaces, task board: not drawn yet

6. Remote

  • Tailnet web view for approvals and watching. No tray change.

Not placed in any increment by the spec, so labelled as such in the mockups: Bonjour discovery (proposed) and backup and restore.

How the theme plugs in

Every tray component reads only --ac-* custom properties: colour roles, harness colours, server swatches, radii and line weight. The default values come from design/system/tokens.json. “Increased contrast” applies that file’s increaseContrast overrides. “Daylight ops” is a new light skin that redefines the same names and nothing else. In Swift, the same split is one token struct in the environment, with the existing components unchanged.
